TandemRLVR — training reasoning agents to remain legible to weaker overseers

The question I keep coming back to: if a model is smarter than the person checking it, what exactly is that person checking? TandemRLVR is my attempt to turn that worry into something I can actually measure.

where this came from

I kept reading about scalable oversight and feeling like the problem was being described rather than tested. Everyone agrees that as models get stronger, checking their work gets harder. Fewer people seem to be measuring it. So I built a setup where the checking is the whole experiment.

The trick I landed on is to stop using a human as the overseer and use a deliberately weaker model instead. That gives me something I can run thousands of times without needing thousands of people.

the loop

task → senior reasoning → junior completion → verifier → metrics

A strong "senior" model reasons partway through a problem and hands over. A weaker "junior" model has to pick up that trace and finish the job. A programmatic verifier then checks the final answer, so correctness is never a matter of opinion.

The clever bit — and honestly the bit I'm most pleased with — is what this setup rules out. If the senior just blurts the answer, the junior succeeds but nothing has been demonstrated. So I score for leakage as well as success. The senior has to be genuinely helpful without giving the game away, which is much closer to what good explanation actually is.

what I'm measuring

Rather than one number, the process reward is a weighted blend:

  • Legibility (0.30) — can the trace be followed at all?
  • Leakage (0.25) — did the senior sneak the answer through?
  • Relevance (0.25) — is the reasoning about this problem, or generic waffle?
  • Usefulness (0.20) — did it actually help the junior get there?

Tasks span arithmetic, logic, list transformation and code tracing — deliberately boring domains, because I want the reasoning to be the variable, not the subject knowledge.

how it's built

  • Stages 1–2 — deterministic task generation and the evaluation scaffolding, with heuristic agents as fixed baselines.
  • Stage 3 — real local LLM agents via Ollama, with the heuristics kept as controls so I can tell model gains from harness noise.
  • Stage 4 — the process-reward metrics above.
  • Stage 5 — generalisation splits: in-distribution, out-of-distribution, and deliberately stress-shifted.
  • Stage 6 — a bandit optimising over handoff prompt strategies rather than model weights, which keeps the whole thing runnable on my own machine.
  • Stage 7 — report and figure generation, so every claim traces back to a run.

what's actually happened so far

Stage 6 proved the optimisation loop works — it does find better handoff strategies, and the in-distribution and out-of-distribution numbers improve. Then it falls over under stress shifts, which was the genuinely interesting result. A strategy that makes reasoning more legible on familiar problems doesn't necessarily hold when the problem shape changes. Legibility looks less like a property you train in once and more like something that has to survive distribution shift, same as everything else.

I want to be straight about the limits: these are preliminary numbers, run on local models, and they need proper multi-seed validation before I'd defend them anywhere. Single runs are a hypothesis, not a finding. That's the next job.

where I'd take it

More seeds and error bars first, then harder task families, then the version I really want — using the process reward as an actual training signal rather than just a measurement. It's also the work I'd most like to do somewhere with people who've thought about oversight for longer than I have, which is partly why I'm building it in the open.
